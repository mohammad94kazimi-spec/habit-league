# چالش عادت‌ها

اپ وب (PWA) برای برنامه‌ریزی روزانه + ساخت/ترک عادت + رقابت امتیازی لیگی بین چند نفر.
معماری کاملاً رایگان: **Supabase** (دیتابیس Postgres + احراز هویت + API، رایگان همیشگی) +
یک هاست استاتیک رایگان برای فایل‌های اپ (Cloudflare Pages یا GitHub Pages).
هیچ سروری نداری که نگهش داری — فقط چند فایل استاتیک که مستقیم با Supabase حرف می‌زنن.

## اگه قبلاً تا fix4.sql را اجرا کردی

فایل `fix5.sql` را هم در **SQL Editor** اجرا کن — دو ستون برای فایل صوتی کارها، یک bucket خصوصی
Storage به اسم `task-audio` (حداکثر ۱۰ مگابایت برای هر فایل) و قوانین دسترسی‌اش رو می‌سازه.
بدون این پچ، بقیه‌ی اپ عادی کار می‌کنه و فقط ضمیمه‌کردن صوت خطا می‌ده.

## اگه قبلاً fix.sql و fix2.sql و fix3.sql را اجرا کردی

فایل `fix4.sql` را هم اجرا کن — فیلد زمان مشخص (ساعت:دقیقه) رو به کارها اضافه می‌کنه.

## اگه قبلاً fix.sql و fix2.sql را اجرا کردی

فایل `fix3.sql` را هم در **SQL Editor** اجرا کن — توضیحات کار، تاریخ انجام‌شدن، و برچسب
گروه برای کارهای دوره‌ای رو اضافه می‌کنه.

## اگه قبلاً schema.sql (و fix.sql) را اجرا کردی

فایل `fix2.sql` را هم در **SQL Editor** اجرا کن — دسته‌بندی‌های قابل‌ویرایش و درجه‌ی
اهمیت (۱ تا ۵) را اضافه می‌کند. بعدش فایل‌های `index.html`، `app.js` و `style.css` تازه
را جایگزین نسخه‌ی قبلی روی هاستت کن.

## اگه قبلاً فقط schema.sql را اجرا کردی (بدون fix.sql)

فایل `fix.sql` را باز کن، محتواش را در **SQL Editor** پروژه‌ی Supabase پیست کن و **Run** بزن.
این پچ مشکل «دکمه‌ی ساخت لیگ/اضافه کردن عادت هیچ اتفاقی نمی‌افته» را حل می‌کند (یک باگ در
قوانین امنیتی RLS بود) و ستون دسته‌بندی کارها را هم اضافه می‌کند. بعدش فایل‌های `index.html`،
`app.js` و `style.css` تازه را هم جایگزین نسخه‌ی قبلی روی هاستت کن (یا دوباره push/deploy کن).

## آفلاین‌بودن و همگام‌سازی

- **پوسته‌ی اپ** (HTML/CSS/JS، کتابخانه‌ی Supabase و **فونت وزیرمتن**) همگی روی خود هاست هستن و
  توسط Service Worker کش می‌شن؛ پس هیچ منبع خارجی (مثل Google Fonts) برای باز شدن اپ لازم نیست و
  بعد از اولین بازِ موفق، اپ بدون اینترنت هم باز می‌شه. پوشه‌ی `fonts/` حتماً کنار بقیه آپلود بشه.
- **وضعیت اپ روی گوشی ذخیره می‌شه** (IndexedDB). با بستن و دوباره باز کردنِ اپ، حتی آفلاین و حتی با
  توکن منقضی‌شده، همون چیزی که قبلاً می‌دیدی (به‌اضافه‌ی تغییرات هنوز-ارسال‌نشده) نمایش داده می‌شه.
- **تشخیص «به سرور وصل نیستی»**: وقتی وای‌فای وصله ولی اینترنت فیلتره، مرورگر خودش رو آنلاین
  می‌دونه. اپ از روی نتیجه‌ی درخواست‌ها (و یک timeout حدود ۱۲ ثانیه) می‌فهمه سرور در دسترس نیست،
  تغییرات رو در صف می‌ذاره و نشان بالای صفحه می‌گه «📴 به سرور وصل نیستی — N مورد در انتظار».
- **صف همگام‌سازی**: ترتیب حفظ می‌شه، ارسال مجدد تکراری ایجاد نمی‌کنه (upsert بدون تغییر در صورت
  وجود)، و اگه یک مورد به‌طور دائمی رد بشه (مثلاً چون چیزی که بهش وابسته بود حذف شده) کنار گذاشته
  می‌شه تا بقیه‌ی صف گیر نکنه؛ در این حالت نشان «⚠ N تغییر ناموفق» ظاهر می‌شه و با لمسش جزئیات رو
  می‌بینی. کار دارای دسته‌ای که دسته‌اش پاک شده بدون دسته ذخیره می‌شه.
- **جدول لیگ** هر بار تب لیگ رو باز کنی، به اپ برگردی، دکمه‌ی «↻ تازه‌سازی» رو بزنی، یا هر ۴۵ ثانیه
  (وقتی تب بازه) تازه می‌شه و زمان آخرین به‌روزرسانی (یا «آفلاین، داده‌ی ذخیره‌شده») نشون داده می‌شه.
- **عوض‌شدن روز** وقتی اپ باز مونده تشخیص داده می‌شه و تیک‌های دیروز دیگه به‌عنوان امروز نمایش
  داده نمی‌شن. «روزِ انجام» هر کار بر اساس ساعت محلیِ گوشی حساب می‌شه (نه UTC).
- ساخت حساب و ساخت/پیوستن به لیگ، و ضمیمه‌کردن/پخش فایل صوتی همچنان به اینترنت نیاز دارن.

### تست‌های خودکار (اختیاری، فقط برای توسعه)
پوشه‌ی `tests/` شامل تست‌های اپ با jsdom و یک سرور شبیه‌سازی‌شده‌ست: `cd tests && npm install && npm test`.
برای اجرای اپ لازم نیست و می‌تونی موقع آپلود نذاریش.

## یادآوری/آلارم (Web Push) — تصمیم گرفته شده، هنوز پیاده‌سازی نشده

گزینه‌ی Web Push واقعی رو انتخاب کردی. هروقت خواستی پیاده‌سازیش کنیم بگو — نیاز به یک جدول
push-subscriptions، یک Edge Function زمان‌بندی‌شده در Supabase، و گرفتن اجازه‌ی اعلان از کاربر
در اپ داره.

## ۱) ساخت پروژه‌ی Supabase (برای نصب تازه)

1. به [supabase.com](https://supabase.com) برو، رایگان ثبت‌نام کن و یک پروژه‌ی تازه بساز.
2. از منوی سمت چپ برو به **SQL Editor**، محتوای فایل `schema.sql` را کامل کپی کن، پیست کن و **Run** بزن.
   این کار جدول‌ها، قوانین امنیتی (RLS) و توابع امتیازدهی را می‌سازد.
3. از **Project Settings → API**، دو مقدار را کپی کن:
   - `Project URL`
   - `anon public` key

   > نکته‌ی امنیتی: کلید `anon` برای استفاده در فرانت‌اند طراحی شده و افشای آن مشکلی ندارد —
   > تمام محدودیت‌های دسترسی از طریق RLS در خود دیتابیس اعمال می‌شود، نه با مخفی نگه‌داشتن این کلید.

4. (اختیاری ولی توصیه‌شده) از **Authentication → Providers**، اگر نمی‌خوای اعضای لیگ ایمیلشون
   را تایید کنن، گزینه‌ی *Confirm email* را در **Authentication → Sign In / Providers → Email**
   خاموش کن تا بلافاصله بعد از ثبت‌نام وارد اپ بشن.

## ۲) وصل کردن اپ به Supabase

فایل `config.js` را باز کن و این دو مقدار را جایگزین کن:

```js
window.APP_CONFIG = {
  SUPABASE_URL: "https://xxxxxxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi....",
};
```

## ۳) هاست رایگان (Cloudflare Pages)

1. یک ریپوی تازه در GitHub بساز و همه‌ی فایل‌های این پوشه (`index.html`, `style.css`, `app.js`,
   `config.js`, `manifest.json`, `sw.js`, `icons/`) را داخلش push کن.
2. به [pages.cloudflare.com](https://pages.cloudflare.com) برو، با GitHub وارد شو، ریپو را انتخاب کن.
3. تنظیمات build را همین‌طور خالی بگذار (این یک سایت استاتیک ساده است، نیازی به build نیست) —
   فقط "Deploy".
4. چند ثانیه بعد یک آدرس مثل `habit-league.pages.dev` می‌گیری. همین آدرس را روی هر دو گوشی
   باز کنید و از منوی کروم گزینه‌ی **افزودن به صفحه‌ی اصلی** را بزنید تا مثل یک اپ نصب بشه.

> جایگزین: GitHub Pages هم دقیقاً همین‌جوری کار می‌کنه (Settings → Pages → انتخاب برنچ).

## ۴) استفاده

1. هر نفر (مثلاً تو و همسرت) جدا ثبت‌نام می‌کنید.
2. نفر اول یک لیگ می‌سازه (تب اولیه‌ی بعد از ورود) و کد دعوت شش‌رقمی می‌گیره.
3. نفر دوم با همون کد به لیگ می‌پیوندد.
4. هرکس عادت‌های خودش را در تب «عادت‌ها» تعریف می‌کنه (ایجاد عادت / ترک عادت).
5. هر روز در تب «امروز» وضعیت هر عادت را با ✓ یا ✕ ثبت می‌کنید.
6. امتیازها خودکار محاسبه می‌شن و در تب «لیگ» جدول امتیازات زنده رو می‌بینید.
7. در تب «کارها» موقع نوشتن اسم کار و زدن ＋، یک مودال باز می‌شه: دسته‌بندی (قابل افزودن/ویرایش/حذف
   از دکمه‌ی «⚙ دسته‌ها»)، درجه‌ی اهمیت (۱ تا ۵ ستاره)، و تاریخ انجام با تقویم شمسی — یا می‌تونی
   تیک «بدون تاریخ مشخص» را بزنی تا کار بدون تاریخ ثبت بشه. لیست کارها بر اساس اهمیت و بعد تاریخ
   مرتب می‌شه و با چیپ‌های بالای لیست می‌تونی بر اساس دسته‌بندی فیلترش کنی.
8. موقع ساخت کار تازه (نه ویرایش)، می‌تونی تیک «کار دوره‌ای است» رو بزنی: الگوی تکرار (هر روز /
   روزهای مشخصی از هفته / هرماه همین روز / هر چند روز یک‌بار) و «تعداد کل دفعات تکرار (شامل
   اولین)» (تا ۳۶۵) رو انتخاب می‌کنی و همه‌ی نمونه‌ها خودکار در تاریخ‌های محاسبه‌شده ساخته می‌شن.
   در الگوی هفتگی، اولین نمونه اولین روزِ انتخاب‌شده‌ی هفته در/بعد از تاریخ پایه‌ست (مثلاً «هر
   یکشنبه، ۵۰ بار» دقیقاً ۵۰ یکشنبه می‌سازه).
   برای ویرایش، روی هر نمونه از کار دوره‌ای که بزنی، بالای فرم یک انتخاب‌گر «اعمال تغییرات روی»
   هست: «فقط همین کار» یا «همه‌ی تکرارهای انجام‌نشده» (عنوان، دسته‌بندی، اهمیت، توضیحات و زمان
   برای همه یک‌جا عوض می‌شه؛ تاریخ هر نمونه و کارهای انجام‌شده دست‌نخورده می‌مونن). دکمه‌ی حذف هم
   از همین انتخاب‌گر تبعیت می‌کنه.
9. تیک «افزودن توضیحات» هم یک کادر متن باز می‌کنه؛ توضیحات هر کار با نگه‌داشتن موس روی آن کار در
   لیست به‌صورت tooltip نشون داده می‌شه.
10. با تیک‌زدن یک کار به‌عنوان انجام‌شده، از لیست اصلی «کارهای من» خارج می‌شه و به بخش «کارهای
    انجام‌شده» (پایین همون تب، قابل نمایش/پنهان‌کردن) منتقل می‌شه؛ تاریخ انجام‌شدنش هم ذخیره و
    نمایش داده می‌شه. اگر همه‌ی کارهای یک روز انجام شده باشن، آن روز در تقویم صفحه‌ی امروز سبز
    رنگ می‌شه.
11. در لیست «کارهای من» از هر کار دوره‌ای فقط نزدیک‌ترین نمونه‌ی انجام‌نشده نشون داده می‌شه (به‌همراه
    «🔁 N تکرار دیگر»)؛ با انجام‌دادنش نمونه‌ی بعدی خودکار ظاهر می‌شه. تقویم و لیست هر روز همه‌ی
    نمونه‌ها رو نشون می‌دن.
13. فایل صوتی: در مودال کار، دکمه‌ی «🎧 افزودن فایل صوتی» (mp3، m4a، wav و …؛ حداکثر ۱۰ مگابایت).
    فایل قبل از ذخیره قابل پخش‌کردنه و بعد از ذخیره، در مودال ویرایش با یک پخش‌کننده نمایش داده
    می‌شه؛ کارهایی که صوت دارن نشان 🎧 می‌گیرن. در کار دوره‌ای، یک فایل بین همه‌ی نمونه‌ها مشترکه
    و با «اعمال تغییرات روی همه‌ی تکرارها» یک‌جا عوض یا حذف می‌شه. فایل‌هایی که دیگه هیچ کاری
    ازشون استفاده نمی‌کنه خودکار از Storage پاک می‌شن. ضمیمه‌کردن و پخش نیاز به اینترنت دارن.
    ضبط مستقیم: دکمه‌ی «🎙 ضبط صدا» کنار «افزودن فایل صوتی» هست. بعد از اجازه‌ی میکروفون، ضبط با
    تایمر شروع می‌شه؛ «⏹ پایان ضبط» فایل رو به کار ضمیمه می‌کنه (قابل پخش قبل از ذخیره)، «لغو» دور
    می‌ندازه، و اگه وسط ضبط روی «ذخیره» بزنی ضبط خودکار تموم و ضمیمه می‌شه. ضبط با رسیدن به سقف
    ۱۰ مگابایت خودکار متوقف می‌شه. ضبط‌ها همون مسیر فایل‌های صوتی (آپلود، اشتراک بین تکرارها،
    پاک‌سازی) رو دارن. اپ باید با HTTPS باز بشه (Cloudflare Pages همین‌طوره) تا میکروفون کار کنه.
11. همه‌ی مودال‌ها (افزودن/ویرایش کار، کارهای یک روز، مدیریت دسته‌بندی‌ها) با کلید Esc هم بسته
    می‌شن.
12. یک تب تازه «📊 آمار» اضافه شد (بدون نیاز به تغییر دیتابیس — همه‌چیز از همون دیتای کارها و
    لیگ محاسبه می‌شه): کارت‌های خلاصه (کارهای تکمیل‌شده، روزهای بی‌نقص، استریک فعلی/بهترین،
    مجموع امتیاز لیگ)، نمودار میله‌ای هفتگیِ قابل‌جابجایی بین هفته‌ها با پیام هوشمند و نرخ تکمیل،
    نمودار دایره‌ای توزیع کارهای انجام‌شده بر اساس دسته‌بندی (با فیلتر ۷/۳۰/۹۰ روز یا همه)، و
    نقشه‌ی حرارتی سالانه (با انتخاب سال و کلیک روی هر روز برای دیدن جزئیاتش).

## نحوه‌ی امتیازدهی (قابل تغییر در جدول `habits`)

- انجام موفق روزانه: `+۱` امتیاز پایه
- هر ۷ روز پیاپی موفق: `+۳` امتیاز پاداش استریک (و استریک با یک شکست ریست می‌شه)
- لغزش/عدم انجام: `−۱` امتیاز جریمه

این عددها (`base_points`, `penalty_points`, `streak_bonus_every`, `streak_bonus_points`) برای هر
عادت جدا در جدول `habits` قابل تغییرن — می‌تونی مستقیم از Supabase Table Editor ویرایششون کنی،
یا بعداً یک فرم تنظیمات به اپ اضافه کنیم.

## محدودیت‌های نسخه‌ی رایگان که باید بدونی

- **Supabase Free**: دیتابیس تا ۵۰۰ مگابایت (برای این اپ به‌راحتی کافیه)، و اگر پروژه **۷ روز**
  کاملاً بدون درخواست بمونه به حالت pause می‌ره — با اولین باز کردن اپ توسط هرکدوم از اعضا
  (که روزانه چک-این می‌کنید) خودکار فعال می‌مونه، پس در عمل مشکلی پیش نمیاد.
- **Cloudflare Pages / GitHub Pages**: رایگان همیشگی، بدون محدودیت زمانی.
- دسترسی از ایران به Supabase و Cloudflare معمولاً بدون فیلترشکن ممکنه، ولی چون این سرویس‌ها
  خارج از ایران هستن، ممکنه گاهی کیفیت اتصال نوسان داشته باشه. اگر در عمل با قطعی/کندی مکرر
  مواجه شدید، جایگزینی مثل هاست ایرانی (لیارا) با یک بک‌اند Flask هم گزینه‌ی قابل‌اجراست
  که در گفتگو دربارش صحبت کردیم.

## توسعه‌های بعدی که می‌شه اضافه کرد

- اعلان/یادآوری روزانه (Push Notification از طریق Web Push)
- تاریخچه و نمودار پیشرفت هر عادت
- چند لیگ هم‌زمان برای هر کاربر
- ویرایش امتیازدهی هر عادت از داخل خود اپ (نه فقط از Supabase)
